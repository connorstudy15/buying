# 10 条 implicit constraint 的 DIRECT / DECOMPOSE 独立复核提示词

你是一名独立的 RAG Query Planner 评测审核员。请只根据用户 Query 本身，判断检索策略应该是 `DIRECT` 还是 `DECOMPOSE`。

## 隔离要求

- 不要读取知识库正文、候选池、现有标签、实验报告或当前 QueryProcessor 输出。
- 不要根据“系统现在能不能召回”判断策略，只判断问题本身的信息需求结构。
- 不要假定这些题目前被标成什么模式。
- 不要把“出现两个商品”“可能需要两篇文档”“一句话有两个问法”直接等同于 DECOMPOSE。

## 判断口径

选择 `DIRECT`，当且仅当：

- 问题只有一个主要信息需求；或者
- 后半句只是前半句的场景、条件、例子或判断目标；或者
- 一个完整检索 Query 可以自然表达全部需求，拆开不会带来独立证据覆盖收益。

选择 `DECOMPOSE`，当且仅当：

- 至少存在两个互不重叠、可以独立检索的信息需求；并且
- 任意一个需求都可能单独召回成功或失败；并且
- 最终回答必须组合这些需求的证据；并且
- 不拆分时，单一 Query 有较明显概率只召回其中一类证据。

即使用户只有一个最终判断目标，如果该判断必须组合两个可独立检索、可独立失败的 gold evidence needs，也应标为 `DECOMPOSE`。

隐含约束只在场景与商品形成高确定性关联时才算信息需求，例如明确“坐飞机携带含锂电设备”可以考虑航空电池限制。不要仅因出现国家名，就自动增加海关、税费或当地政策查询。

## 待判断 Query

1. `v4-043`：暑假坐飞机去欧洲露营，想带移动电源和露营灯，出发前该核对什么？
2. `v4-044`：去日本住民宿，想把粗陶茶具装进行李带过去，有什么要提前留意的？
3. `v4-045`：坐廉航去东南亚，只背一个折叠双肩包，不加购行李额能行吗？
4. `v4-046`：去美国住几个月，家里的充电器和小电器能直接带过去用吗？
5. `v4-047`：想把竹木陶餐具寄给澳洲的朋友，寄出前该确认什么？
6. `v4-048`：我要搬到加拿大，想把棉麻织物和收纳用品一起寄过去，怎么预估运费才不吃亏？
7. `v4-049`：冬天去雪山露营，头灯和露营灯还能正常用吗？
8. `v4-050`：夏天去海边露营，想把露营灯放在沙滩边用，挑选时有什么要注意的？
9. `v4-051`：想把轻量天幕寄去英国，知道商品不算重，但邮费会不会仍然很贵？

## 输出要求

逐题输出 JSON 数组，每项严格包含：

```json
{
  "id": "v4-043",
  "strategy": "DIRECT 或 DECOMPOSE",
  "information_needs": [
    {
      "need_id": "简短英文ID",
      "need": "用中文说明独立信息需求",
      "independently_retrievable": true
    }
  ],
  "why_not_other_strategy": "为什么不选择另一种策略",
  "confidence": 0.0,
  "ambiguity": "如果存在歧义，说明歧义来自哪里；没有则为空字符串"
}
```

额外要求：

1. `DIRECT` 原则上只能列一个主要 information need。如果你列出两个真正独立、可分别失败的需求，就不应选择 DIRECT。
2. `DECOMPOSE` 必须列出至少两个信息需求，每个需求都能单独构造成检索 Query。
3. 不允许用“问题比较复杂”作为拆分理由。
4. 不允许因为知识可能分散在多篇文档中就拆分。
5. 不输出答案，不判断具体政策或商品结论。

JSON 数组之后，再给出简短中文总结：

- DIRECT 数量和 ID；
- DECOMPOSE 数量和 ID；
- 置信度低于 0.85 的 ID；
- 最容易产生分歧的 3 条及原因；
- 你建议如何用这些标签计算 `DECOMPOSE Trigger Precision`，并说明哪些低置信度题不应直接作为硬门禁真值。
