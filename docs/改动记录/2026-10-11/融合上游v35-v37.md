# 融合上游 v3.5–v3.7

## 需求与版本

用户要求同时融合会话搜索、上下文用量及新版页面（v3.5），模型网关和配置管理（v3.6），任务自动化、订单与收藏整合（v3.7）。本次只准备本地融合版本，统一测试后再安排发布。

- 融合分支：`codex/integrate-upstream-v35-v37`。
- 回退基线：`37df884`，标签 `cloud-beta-20261011`，已保存到用户 GitHub 仓库。
- 上游：`pao-coder66/globex-agent`，提交 `ddd7e5be1af4bb474f3af325f3d5113051c1c013`。
- 两仓历史不连通；当前项目起始代码最接近上游 `c9cd1ca`。用该版本做文件级三方融合，未整体替换目录。
- 上游功能及其实现归原作者；本日记录融合工作，不将上游开发日期改写为本日。

## 实现

1. 合入历史会话搜索、执行轨迹、上下文显示、新版商品与订单收藏页面。
2. 合入版本化模型目录、连接验证、加密凭据、会话模型选择及上下文窗口设置。模型管理只允许配置的管理员身份；普通访问者不能修改连接。
3. 合入任务调度、任务运行记录、暂停/恢复/归档等接口与界面。
4. 保留当前项目的 HMAC 登录、服务端身份验证、知识查询改写、资源治理、调用计量和本地诊断模块。新模型配置路径也接入资源估算与计量。
5. 精排同时兼容独立密钥、百炼嵌套协议、完整结果校验及相同文本去重，保留本地资源账本接口。
6. 补齐上游模型配置和 v2/v3 合成商品夹具，更新依赖锁。云端 Dockerfile 将 v3 商品夹具放在命名数据卷之外，避免被 `/app/data` 挂载遮蔽。
7. 云端 Compose 的普通 Redis 队列 worker 设置 `AUTOMATION_WORKER_MODE=off`，默认由 API 的 embedded 调度器处理定时任务。

## 启用和回退

- 尚未修改云端部署、真实 `.env` 或已有数据库。邀请链接功能不属于这三组上游功能，目前仍待实现。
- 模型管理员配置：在部署 `.env` 的 `MODEL_ADMIN_BUYERS` 中填写实际签发的买家身份 ID。不要把密钥放进前端构建变量。
- 模型加密主密钥默认存放在数据卷的 `.secrets/model_registry.key`；备份必须包含该文件和数据库，丢失该密钥将无法解密已保存连接。
- 更新前对应用、Redis、Qdrant 数据卷做可恢复备份，停止领取新任务并等待在途任务结束；不能用新旧两个调度器同时写同一数据卷。
- 数据格式和上下文策略有变化，回退应同时恢复发布前的数据备份与基线镜像；仅切换旧镜像不保证新版数据可读。
- 正式公开访问仍需要 HTTPS、邀请入口和云端真实链路验收。当前测试不构成公开发布验收。
