# 两轮更新说明与部署状态

## 第一轮：购物需求确认与交互体验

- 新增 `show_shopping_requirements` 工具，将购物目标、预算、用途、尺寸等整理为可编辑需求卡。
- 显示明确提取、AI 推测、未知三种状态，并展示原话来源、硬条件和偏好。提交前不视为已确认。
- 支持修改、清空、确认和持久恢复；清空项保持未知，修改后不沿用原硬条件标签，确认后继续同会话选购。
- 复用表单的归属校验、版本和幂等提交；需求确认不会创建订单或写长期偏好。
- 用户向上查看聊天历史时显示“回到最新”，点击后回到底部并恢复消息跟随。
- 失败后恢复最近一次选购需求；“重试本轮”保留原输入，便于继续编辑。
- 增加需求保存成功状态、保存中无障碍标记、淡紫主题动效和减少动效支持。
- 保留 `frontend/public/p0-preview.html` 作为交互原型；其中模拟反馈不等于真实后端能力。

实现和边界见 `shopping-requirements-review.md`，简历表述见 `product-resume-and-validation-20261017.md`。

## 第二轮：回归、跨平台与部署兼容修复

- 修复 Skill/偏好页面测试中的异步认证等待和旧品牌选择器。
- 模型 YAML、Skill 评测集和 HTML 报告显式使用 UTF-8；Prompt YAML 优先 UTF-8/BOM 并兼容 GB18030，原始字节哈希不变。
- 旧 Prompt 缺少 query_processor 时回退旧知识检索，不跨版本混用 Prompt 正文。
- 云更新流程测试显式使用 UTF-8 读写脚本和解码输出。
- Shell 文件使用 LF；交付包的 RELEASE_COMMIT 也已修正为 LF，避免 Linux 版本校验失败。
- 修复传统 Docker 构建器读取 frontend/.dockerignore 时排除 dist 的问题。
- 提供 tar.gz 更新包及 SHA-256；本机组装目录、压缩包和数据库不入库。
- 将特定版本的 Prompt 兼容升级准备补丁源码保存在 `scripts/releases/prompt-repair-20261017/`，它绑定本次镜像代码指纹和已确认的服务器来源版本，不能用于任意后续版本。

Prompt 准备补丁只生成候选并只读校验，不直接改生产注册表。实际使用 GLOBEX_MANUAL_RELEASE=1 才选择现有人工发布流程；真实模型成对评测未完成时明确记录 INCOMPLETE，不冒充质量门禁通过。升级仍执行来源/代码/工具契约检查、备份和健康检查。
